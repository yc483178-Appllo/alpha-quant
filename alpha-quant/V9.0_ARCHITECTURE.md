## 架构总览

### 设计哲学

V9.0 架构从 V8.0 的"功能堆砌"升级为"**分层解耦 + 智能协作**"模式。核心思想：

- **分层自治**: 每层独立运行，通过 MCP 总线通信
- **技能编排**: 将功能封装为可插拔 Skills，动态组合
- **AI 原生**: 每层内置 AI Agent，支持自主决策与协作
- **可解释性**: XAI 贯穿全链路，每个决策可追溯

## 十层架构详解

### L1: 基础层 (Foundation Layer)

**职责**: 统一市场数据接入与实时行情展示

**核心模块**:
| 模块 | 功能 | V8.0 对应 |
|------|------|-----------|
| MCP Data Gateway | 多源数据统一接入 | enhanced_data_gateway.py |
| Real-time Ticker | 行情跑马灯组件 | 新增 |
| Index Monitor | 主要指数实时追踪 | dashboard_data_bridge.py |
| Sector Heatmap | 板块涨跌热力图 | 新增 |

**MCP 协议**: `viking://data/market/{symbol}`

---

### L2: 信号层 (Signal Center)

**职责**: 交易信号的统一生成、过滤与管理

**核心模块**:
| 模块 | 功能 | 技术方案 |
|------|------|----------|
| Signal Generator | 多因子信号合成 | GP遗传编程 + Transformer |
| Signal Filter | 噪声过滤与平滑 | Kalman + 小波去噪 |
| Confidence Evaluator | 信号置信度评估 | 贝叶斯推理 |
| Position Manager | 动态仓位调整 | Kelly公式 + 风险约束 |

**MCP 协议**: `viking://signal/{strategy_id}/{signal_type}`

---

### L3: 智能体层 (AI Agents Cluster)

**职责**: 多 Agent 协同决策与任务调度

**Agent 类型**:
```python
class StrategyAgent:
    """策略Agent: 负责信号生成与策略执行"""
    role = "signal_generator"
    
class RiskAgent:
    """风控Agent: 实时监控与风险干预"""
    role = "risk_guardian"
    
class ExecutionAgent:
    """执行Agent: 订单拆分与最优执行"""
    role = "order_executor"
    
class MonitorAgent:
    """监控Agent: 系统健康与异常检测"""
    role = "system_watcher"
```

**协作模式**:
- **主从模式**: StrategyAgent 主导，RiskAgent 否决权
- **共识模式**: 重大决策需 2/3 Agent 同意
- **竞速模式**: 多 Agent 生成信号，择优执行

---

### L4: 策略层 (Strategy Pool + Portfolio Builder)

**职责**: 策略库管理与智能组合配置

**策略池分类**:
| 类别 | 策略示例 | 适用 regime |
|------|----------|-------------|
| 趋势跟踪 | 均线突破、动量策略 | bull |
| 均值回归 | 布林带、统计套利 | range |
| 事件驱动 | 财报超预期、政策利好 | event |
| AI 策略 | Transformer-DRL、GP因子 | adaptive |

**组合构建引擎**:
- **AI 配置**: 基于 DRL 的智能权重分配
- **手动配置**: 用户自定义策略组合
- **风险平价**: 等风险贡献配置
- **智能配置**: 基于 regime 检测的自动切换

---

### L5: 分析层 (Analytics Layer)

**职责**: 深度分析与预测模型

**核心引擎**:
| 引擎 | 技术栈 | 功能 |
|------|--------|------|
| 舆情分析 | Kimi LLM + 事件图谱 | 新闻/公告情绪提取 |
| DRL | PPO + Transformer | 端到端交易决策 |
| 元学习 | MAML + Reptile | 快速适应新市场 |
| 事件驱动 | 因果推理 + 冲击模型 | 事件信号生成 |

---

### L6: 风控层 (Risk & Evolution)

**职责**: 全链路风险管理与策略进化

**风控引擎**:
```
风险分解树
├── 市场风险 (VaR, CVaR)
├── 因子风险 (Barra CNE6)
├── 组合风险 (Brinson归因)
└── 操作风险 (异常检测)
```

**拉尾检测系统 (Tail Risk Detection)**:
- 极值理论 (EVT) 监测
- 波动率微笑分析
- 跨资产相关性突变检测

**GP 进化算法 (NSGA-III)**:
- 三目标优化: 收益 / 风险 / 换手率
- 小生境遗传: 保持种群多样性
- 过拟合惩罚: 正则化适应度函数

---

### L7: 执行层 (Execution Layer)

**职责**: 交易全生命周期管理

**六大子系统**:
| 子系统 | 功能 | 关键技术 |
|--------|------|----------|
| 投研中心 | 研报生成与知识管理 | Kimi LLM + PDF导出 |
| 券商管理 | 多券商接入与路由 | 统一 SDK + 双活 |
| 历史知识库 | 交易记录归档与检索 | 向量数据库 |
| 回测引擎 | 策略验证与绩效评估 | Almgren-Chriss |
| 模拟交易 | 虚拟账户与撮合 | A股规则 1:1 |
| 合规审计 | 交易合规与报告生成 | 不可篡改日志 |

---

### L8: 枢纽层 (Hub Layer) - V9.0 新增

**职责**: 系统核心枢纽与智能协调

**四大枢纽**:

#### 8.1 AI 网关 (AI Gateway)
- **多模型路由**: Kimi / GPT-4 / Claude / DeepSeek
- **负载均衡**: 基于成本和质量的智能路由
- **容错切换**: 单点故障自动降级

#### 8.2 Agent 博弈协调器 (Agent Game Coordinator)
- **博弈机制**: 多 Agent 间的竞争与合作
- **激励机制**: 基于贡献度的奖励分配
- **冲突解决**: 仲裁与投票机制

#### 8.3 因子生命周期管理 (Factor Lifecycle Manager)
- **因子发现**: GP 自动挖掘新因子
- **因子验证**: 样本外 + 实时验证
- **因子退役**: 失效检测与自动下线
- **因子监控**: IC、IR、衰减追踪

#### 8.4 实时风控哨兵 (Real-time Risk Sentinel)
- **流式计算**: Flink 实时风险指标
- **熔断机制**: 多层级熔断策略
- **预警推送**: 飞书/钉钉/邮件

### L9: 技能层 (Skills Hub) - V9.0 核心新增

**职责**: 可复用技能编排与 MCP 数据总线

#### 9.1 XAI 可解释 AI 引擎 (Explainable AI)

**三层解释架构**:
```
L3: 全局解释 (Global)
    └── 策略整体逻辑: SHAP 全局特征重要性
    
L2: 局部解释 (Local)
    └── 单次决策原因: LIME / Anchors
    
L1: 反事实解释 (Counterfactual)

```

**解释类型**:
| 场景 | 解释方法 | 输出形式 |
|------|----------|----------|
| 信号生成 | 注意力可视化 | 热力图 |
| 仓位调整 | SHAP 值分解 | 瀑布图 |
| 风险评估 | 规则链追溯 | 决策树 |
| 策略切换 | regime 归因 | 文本报告 |

**技能市场**:

#### 9.3 MCP 数据总线 (Model Context Protocol Bus)

**协议规范**:
```
viking://{layer}/{module}/{resource}?params

示例:
viking://L1/market/000001.SZ?fields=open,high,low,close
viking://L5/sentiment/analyze?text=央行降准
viking://L8/gateway/llm?model=kimi&prompt=...
```

**总线特性**:
- **统一寻址**: URI 格式资源定位
- **类型安全**: 强类型 Schema 校验
- **流式传输**: WebSocket 实时推送
- **缓存层**: Redis 多级缓存

### L10: 协作层 (Collaboration Layer) - V9.0 核心新增

**职责**: 前沿数据与场景模拟

#### 10.1 拥挤度监控系统 (Crowding Monitor)

**拥挤度指标**:
| 维度 | 指标 | 数据源 |
|------|------|--------|
| 资金拥挤 | 融资余额占比 | 交易所 |
| 持仓拥挤 | 机构持仓集中度 | 季报/聚宽 |
| 交易拥挤 | 换手率分位数 | 行情数据 |
| 舆情拥挤 | 热搜排名 | 百度指数 |

**预警信号**:
- 拥挤度 > 80%: 黄色预警
- 拥挤度 > 90%: 红色预警，建议减仓
- 拥挤度 < 20%: 蓝色信号，关注机会

#### 10.2 另类数据接入 (Alternative Data)

**数据源矩阵**:
```
卫星数据: 停车场车辆数 → 零售消费

供应链: 物流轨迹 → 订单预测
        └→ 海关数据 → 进出口

ESG数据: 碳排放 → 政策风险
        └→ 治理评分 → 长期价值
```

**接入方式**:
- API 直连: 有官方接口的数据源
- 爬虫采集: 公开网页数据
- 合作接入: 第三方数据供应商

## 核心新增模块详细设计

### 模块 1: MCP Data Bus (Model Context Protocol)

**设计目标**: 统一十层架构的数据交换协议

**核心概念**:
```
┌─────────────────────────────────────────────────────────────┐
│                    MCP Data Bus                             │
├─────────────────────────────────────────────────────────────┤
│  Publisher ───────┐                                         │
│  (L1 Data)        │         ┌─────────────┐                 │
│                   │────────→│   Topic     │                 │
│  Publisher ───────┤         │  /market/*  │                 │
│  (L5 Signal)      │         └──────┬──────┘                 │
│                   │                │                        │
│  Publisher ───────┘                ↓                        │
│  (L8 Monitor)              ┌───────────────┐                │
│                            │  Message Queue│                │
│  Subscriber ←──────────────│   (Redis/Rmq) │                │
│  (L3 Agent)                └───────┬───────┘                │
│                                    │                        │
│  Subscriber ←──────────────────────┘                        │
│  (L7 Execution)                                             │
└─────────────────────────────────────────────────────────────┘
```

**协议格式**:
```json
{
  "uri": "viking://L1/market/000001.SZ/kline",
  "method": "GET|POST|SUBSCRIBE",
  "headers": {
    "layer": "L3",
    "agent_id": "strategy_agent_01",
    "timestamp": 1712345678,
    "correlation_id": "uuid"
  },
  "payload": {
    "period": "1d",
    "count": 100,
    "fields": ["open", "close", "volume"]
  },
  "priority": 1,
  "ttl": 60
}
```

**实现文件规划**:
- `mcp_bus/core.py`: 核心总线实现
- `mcp_bus/publisher.py`: 发布者 SDK
- `mcp_bus/subscriber.py`: 订阅者 SDK
- `mcp_bus/router.py`: 消息路由
- `mcp_bus/registry.py`: 服务注册发现

### 模块 2: Skills Hub 技能中心

**设计目标**: 将系统功能封装为可复用、可编排的技能单元

**技能生命周期**:
```
开发 → 测试 → 注册 → 发现 → 编排 → 执行 → 监控 → 迭代
```

**技能分类**:
| 类别 | 示例 | 层 |
|------|------|-----|
| DataSkill | 获取行情、获取财务数据 | L1 |
| SignalSkill | 生成信号、过滤噪声 | L2 |
| AgentSkill | 执行策略、风控检查 | L3 |
| AnalysisSkill | 舆情分析、归因分析 | L5,L6 |
| ExecutionSkill | 下单、撤单、查询 | L7 |
| XAISkill | 生成解释、可视化 | L9 |

**技能编排 DSL**:
```yaml
workflow:
  name: "晨间交易策略"
  trigger: "cron: 09:15"
  steps:
    - skill: "market_data.fetch"
      output: "market_snapshot"
      
    - skill: "sentiment_analysis.analyze"
      input: "$market_snapshot.news"
      output: "sentiment_score"
      
    - skill: "signal_generator.generate"
      inputs:
        - "$market_snapshot"
        - "$sentiment_score"
      output: "trading_signals"
      
    - skill: "risk_agent.validate"
      input: "$trading_signals"
      condition: "confidence > 0.7"
      
    - skill: "execution_agent.execute"
      input: "$trading_signals"
```

**实现文件规划**:
- `skills_hub/registry.py`: 技能注册中心

### 模块 6: 扩散场景生成器

**设计目标**: 基于扩散模型生成市场压力测试场景

**技术方案**:
```python
import torch
import torch.nn as nn

class MarketDiffusionModel(nn.Module):
    """
    市场数据扩散模型
    基于 DDPM 架构，专门训练用于生成合理的股价路径
    """
    
    def __init__(self, input_dim=10, hidden_dim=256, num_steps=1000):
        self.input_dim = input_dim  # 多资产收益率
        self.num_steps = num_steps  # 扩散步数
        
    def forward_diffusion(self, x_0, t):
        """前向扩散: 逐步添加噪声"""
        noise = torch.randn_like(x_0)
        alpha_t = self.alpha_schedule[t]
        x_t = torch.sqrt(alpha_t) * x_0 + torch.sqrt(1 - alpha_t) * noise
        return x_t, noise
        
    def reverse_diffusion(self, x_t, t, condition):
        """反向去噪: 生成场景"""
        # condition 可包含: 市场状态、目标波动率等
        predicted_noise = self.denoise_network(x_t, t, condition)
        x_t_minus_1 = self.step_backward(x_t, predicted_noise, t)
        return x_t_minus_1
```

**场景生成类型**:
1. **历史重演**: 输入历史危机时期，生成变体场景
2. **极端压力**: 生成百年一遇的市场冲击
3. **尾部事件**: 基于当前市场生成尾部风险场景
4. **蒙特卡洛**: 生成大量路径用于 VaR 计算

**实现文件规划**:

- `diffusion/scenarios.py`: 场景生成器
- `diffusion/trainer.py`: 模型训练
